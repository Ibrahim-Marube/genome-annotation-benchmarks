# genome-annotation-benchmarks

Benchmarking ab initio gene prediction against a curated reference annotation,
run on the University of Potsdam HPC cluster with a reproducible Snakemake
workflow. Built while learning genome annotation and sequence bioinformatics
(MSc Bioinformatics, Universität Potsdam).

## Question

How accurately do two classic prokaryotic gene finders, **Prodigal 2.6.3** and
**Glimmer3 3.02**, reproduce the RefSeq annotation of *E. coli* K-12 MG1655,
and where do they go wrong?

## Data

NCBI RefSeq assembly GCF_000005845.2 (NC_000913.3, 4.64 Mb). The genome sequence
is the only input to the predictors; the RefSeq GFF3 is the answer key. The
reference gene set is the 4,290 non-pseudogene CDS in that file.

## Method

- **Prodigal:** `prodigal -p single`.
- **Glimmer3:** standard self-training recipe (`long-orfs` → `extract` →
  `build-icm` → `glimmer3 -o50 -g110 -t30`), default start-codon probabilities
  (ATG/GTG/TTG = 0.6/0.3/0.1). Nothing was tuned.
- **Scoring:** a predicted gene is matched to a reference gene by strand and stop
  coordinate. *Found* = same stop; *exact* = same stop and same start.
  Sensitivity = matched / reference genes; precision = matched / predicted genes.
- **Error analysis:** unmatched predictions and missed genes are classified by
  what they overlap in the reference (`analyze_errors.py`).
- Glimmer3 reports gene ends differently from Prodigal, so `glimmer_to_gff.py`
  checks the genome sequence to detect whether the stop codon is included
  (it was, for 4,397 of 4,397 predictions).

## Results

| Tool | Predicted | Found (sens / prec) | Exact (sens / prec) | Start disagreements |
|---|---|---|---|---|
| Prodigal | 4,319 | 96.0% / 95.4% | 90.5% / 89.9% | 236 |
| Glimmer3 | 4,397 | 94.5% / 92.2% | 71.3% / 69.5% | 998 |

(`results/comparison.md` is generated by the workflow.)

Where the errors are:

| | Prodigal | Glimmer3 |
|---|---|---|
| Extra predictions (not in reference) | 200 | 342 |
| …inside a RefSeq pseudogene | 137 | 139 |
| …intergenic | 45 | 120 |
| …antisense to a reference gene | 12 | 56 |
| …same strand, different stop | 6 | 27 |
| Missed reference genes | 171 | 235 |
| …shorter than 300 nt | 157 | 195 |

### What this shows

- Both tools find about 95% of genes. Finding genes is largely solved for
  *E. coli*; the differences are in the details.
- Most "false positives" for both tools lie inside RefSeq pseudogenes (decayed
  genes that still look protein-coding). Counting those as defensible, precision
  is about 98.5% for Prodigal and 95.2% for Glimmer3.
- **Start-codon choice is the main difference:** Glimmer3 disagrees with RefSeq
  on the start of 998 genes against 236 for Prodigal. Glimmer3's default start
  probabilities were not tuned, which may contribute; this is untested.
- Glimmer3 makes more short, spurious predictions (248 of its 342 extras are
  under 300 nt), including four times as many antisense calls.
- Missed genes are overwhelmingly short (under 300 nt) for both tools.

## Limitations

- One genome and default settings. RefSeq start sites are not all
  experimentally verified, so "exact" means agreement with the reference, not
  proof of correctness.
- Matching by stop coordinate ignores genes whose stop is mispredicted
  (reported as one missed plus one extra).

## Reproduce

On the cluster (Debian, Lmod modules, SLURM; the workflow is light enough to run
on the login node):

```bash
git clone https://github.com/Ibrahim-Marube/genome-annotation-benchmarks.git
cd genome-annotation-benchmarks

# Snakemake environment. Snakemake 9's --use-conda needs conda >= 24.7.1, and the
# cluster module is older, so install a newer conda inside the environment:
module load lang/Miniconda3/23.9.0-0
conda create -y -p $WORK/envs/smk --solver=libmamba --override-channels \
  -c conda-forge -c bioconda "snakemake>=8"
conda install -y -p $WORK/envs/smk --solver=libmamba --override-channels \
  -c conda-forge "conda>=24.7.1"
export PATH=$WORK/envs/smk/bin:$PATH

snakemake -s workflow/Snakefile --cores 2 --use-envmodules --use-conda
cat results/comparison.md
```

Set `WORK` to a directory on the cluster's work filesystem. Prodigal comes from
the cluster's `bio/prodigal/2.6.3-GCCcore-10.2.0` module; Glimmer3 is installed by
Snakemake from `envs/glimmer.yaml`. To benchmark another genome, add an entry to
`config.yaml`.

## Layout

```
config.yaml                 genomes and tools to run
envs/glimmer.yaml           conda environment for Glimmer3
workflow/Snakefile          download → predict → convert → score → table
workflow/scripts/           compare_gff.py, analyze_errors.py,
                            glimmer_to_gff.py, make_table.py
results/                    predictions, scores, error analyses, comparison.md
data/                       downloaded genome and reference (not tracked)
```
